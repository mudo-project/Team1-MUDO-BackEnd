# 스레드·비동기 작업 포화 Runbook

1. 학원별 Tomcat busy/max, 비동기 active/queue/rejected, 무거운 작업 active를 확인한다.
2. 요청률·응답시간·오류율과 동시에 비교해 실제 사용자 영향을 확인한다.
3. 보고서·파일 처리 등 무거운 API가 제한을 우회하는지 확인한다.
4. 악성 또는 반복 요청이면 WAF와 애플리케이션 Rate Limit을 우선 적용한다.
5. 상한 변경 전 Task 메모리, 스레드 스택, Hikari Pool과 RDS 연결 예산을 함께 계산한다.
6. 운영 데이터가 없는 환경에서 포화 시험 후 값을 반영한다.
