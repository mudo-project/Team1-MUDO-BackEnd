# lecture 모듈

## 책임과 범위

강의(수업) 개설·배정과 수강생 관리를 담당한다. "통통통"류 경쟁 서비스의 폴더 계층(학년 폴더 → 과목/선생님 폴더 → 학생) 구조가 번잡하다는 판단 아래, **폴더 계층을 없애고 평면 데이터 + 필터/뷰**로 대체하는 방향으로 설계했다.

- **Lecture(강의)**: 학년 + 과목 + 시즌 + 담당 선생님(`users`) + 교실 + 요일/시간대(복수 가능)를 가진 실제 수업 단위. "통통통"의 "고3 겨울방학"(학년+시즌) 폴더와 "과목/선생님"(과목+선생님) 폴더가 2단으로 나뉘어 있던 걸, 계층 없이 `Lecture` 하나가 가진 필터링 가능한 속성들로 평평하게 흡수했다.
- **Grade(학년)**: 초1~초6/중1~중3/고1~고3/N수 고정 목록(enum). `Lecture.grade`(이 강의의 대상 학년)와 `Student.grade`(이 학생의 실제 학년)가 같은 값 집합을 공유한다.
- **Term(시즌/학기)**: "2026 겨울방학 특강", "2026 1학기 정규반"처럼 매 시즌 새로 생기는 이름표. `Subject`/`Classroom`과 동일하게 강의 등록 시 입력한 이름으로 자동 생성(find-or-create)된다. "특강/정규반/내신대비" 같은 구분은 별도 필드로 안 두고 시즌 이름 자체에 녹여 쓴다 (예: "2026 겨울방학 특강" vs "2026 겨울방학 내신대비").
- **Subject(과목)**: 강의에 붙는 이름표 성격의 마스터 데이터. `Classroom`과 동일하게 강의 등록 시 입력한 이름으로 자동 생성(find-or-create)되며, 별도의 "과목 추가" 화면은 없다. 자유 텍스트로 두면 오타로 필터링이 깨지기 쉬워 마스터 테이블로 분리했다.
- **Classroom(교실)**: 강의에 붙는 이름표 성격의 마스터 데이터. 강의 등록 시 이름으로 자동 생성(find-or-create)되며, 별도의 "교실 추가" 화면은 없다.
- **선생님**: 이 모듈이 소유하지 않는다. `users`(직원 계정) 중 한 명을 참조할 뿐이며, 계정 발급은 `users`/`auth` 모듈의 "관리자 직원 계정 발급" 기능이 담당한다. 강의 등록 화면에서는 기존 직원을 이름으로 검색해 선택하는 방식이고, 이 모듈에 "선생님 추가" 화면은 없다.
- **Student(학생)**: 이름/학년/학교/전화번호/부모님전화번호/특이사항을 가진 순수 마스터 데이터. **로그인 계정이 없다** — `users` 테이블과 완전히 분리된 별개 개체다 (그룹웨어 로그인 계정은 학원 관리자가 직원에게만 발급하는 구조).
- **Enrollment(수강 등록)**: `Student` ↔ `Lecture` 다대다 조인. 학생 정보가 강의마다 중복 입력되지 않고 한 번만 존재한다.

## 소유하는 주요 데이터와 상태 (설계안)

| 엔티티 | 주요 필드 | 비고 |
|---|---|---|
| `Term` | `academyId`, `name` | 강의 등록 시 자동 생성 (find-or-create). 예: "2026 겨울방학 특강" |
| `Subject` | `academyId`, `name` | 강의 등록 시 자동 생성 (find-or-create) |
| `Classroom` | `academyId`, `name` | 강의 등록 시 자동 생성 (find-or-create) |
| `Lecture` | `academyId`, `name`, `grade`(enum), `termId`(FK), `subjectId`(FK), `teacherId`(users FK), `classroomId`(FK) | |
| `LectureSchedule` | `lectureId`(FK), `dayOfWeek`, `startTime`, `endTime` | 강의 1개가 여러 요일/시간대를 가질 수 있어 1:N으로 분리 (예: 월/수/금 3~5시 → 3행) |
| `Student` | `academyId`, `name`, `grade`(enum, `Lecture.grade`와 값 공유), `school`, `phone`, `parentPhone`, `note` | 로그인 없음, `users`와 무관 |
| `Enrollment` | `studentId`(FK), `lectureId`(FK), `enrolledAt` | 다대다 조인 |

모든 테이블에 `academyId`(멀티테넌시) 컬럼을 두고, approval/notice에서 반복적으로 발견됐던 학원 간 데이터 누수 버그를 처음부터 방지하기 위해 모든 조회·생성 경로에 요청자 학원 스코프 검증을 포함한다.

### 교실 시간 충돌 정책 (확정)

같은 `classroomId` + `dayOfWeek`에 시간 범위가 겹치는 `LectureSchedule`을 **등록 자체를 막는다** (409 에러로 안내). 시간표 그리드에 겹친 셀이 그려지는 걸 UI 레벨이 아니라 등록 시점에 원천 차단하는 방향으로 결정했다.

## 외부에 공개하는 Application API (설계안)

강의 관리:
- `CreateLectureUseCase` — 강의 등록 (이름/학년(고정값)/시즌명/과목명/선생님(userId)/교실명/요일·시간 복수, 시즌·과목·교실 자동 생성, 시간 충돌 검증)
- `LectureQueryUseCase` — 강의 목록(선생님/교실/학년/과목/시즌 필터) / 상세(수강생 목록 포함) 조회
- 학생 등록/수강 등록 UseCase (설계 예정)

교실 관리:
- `ClassroomQueryUseCase` — 교실 목록 / 교실별 주간 시간표(요일×시간, 강의명·선생님명 포함) 조회

학생:
- `StudentQueryUseCase` — 학생 상세(개인정보 포함) 조회, 특정 학생이 수강 중인 강의 목록 조회

## 다른 모듈 또는 외부 시스템에 요청하는 의존성

- **직원(선생님 후보) 검색·조회 — `users` 모듈에 신규 요청 필요**: 강의 등록 화면에서 담당 선생님을 이름으로 검색해 고르려면 "소속 학원 직원 목록/검색" API가 있어야 하는데, `users` 모듈에는 현재 로그인·토큰 API만 있고 이 기능이 없다(직원 목록 조회 API 자체가 아직 없음). approval의 `ApproverDirectoryPort`, notice의 `NoticeAuthorDirectoryPort`가 각자 `users` 테이블을 직접 읽는 임시 shim으로 구현했다가, `users` 테이블 스키마 변경(컬럼 삭제) 때마다 조용히 깨진 적이 이미 두 번 있다. lecture는 같은 실수를 세 번째로 반복하지 않기 위해, 임시 shim 대신 `users` 담당자(be4)에게 아래 형식으로 정식 Port를 요청한다.

    ```text
    [대상 모듈] users

    [필요한 변경] 소속 학원 직원 이름 검색 Port (예: UserDirectoryPort.searchByName(academyId, keyword))

    [입력] academyId, 검색 키워드(이름)

    [출력] userId, name 최소 Projection 목록 (내부 User 엔티티 노출 안 함)

    [필요한 이유] 강의 등록 시 담당 선생님을 기존 직원 중에서 검색해 선택해야 함

    [영향 범위] lecture 모듈 강의 등록/수정 화면
    ```

    승인 전까지는 이 기능이 막혀 있는 상태로 설계를 진행한다 (구현 착수 전 반드시 확인).
- **인증 사용자 정보**: `global.presentation.security.AuthUser` 사용.
- **권한**: 학생 개인정보(전화번호/부모님전화번호/특이사항)는 민감정보이므로, approval/notice처럼 나중에 권한을 붙이지 않고 **처음부터** `role`/`permission` 시스템에 `STUDENT:READ`, `LECTURE:MANAGE` 같은 권한 코드를 정의하고 컨트롤러에 `@PreAuthorize`를 적용한다.

## 변경 시 주의 사항 / 설계 결정 배경

- **폴더 계층을 의도적으로 배제했다.** 경쟁 서비스(통통통)가 "학년 폴더 → 과목/선생님 폴더(틀) → 학생(데이터)"를 화면에 그대로 노출해 3단 클릭과 폴더별 학생 중복 입력을 유발한다고 판단, `Lecture`를 평면 리스트 + 필터로 설계했다.
- **Classroom은 물리적 자원 스케줄러가 아니라 이름표 + 시간 충돌 검증까지만** 한다. 그 이상의 시설 예약/자원 관리 기능은 이번 범위가 아니다.
- **Student는 로그인 계정을 만들지 않는다.** 학원 그룹웨어 로그인 계정은 관리자가 직원에게만 발급하는 구조이므로, `users` 테이블과 별개의 순수 마스터 데이터로 관리한다.

### 1. 강의 관리 탭

| 페이지 | 내용 |
|---|---|
| 강의 목록 | 선생님/교실/학년/과목/시즌/요일 필터가 있는 강의 리스트. "어떤 선생님이 몇시에 어떤 교실에서 강의하는지" 한눈에 보이는 배정 현황 뷰. 시즌 필터로 "2026 겨울방학 특강"만 걸러보는 식의 통통통 폴더 대체 |
| 강의 등록 (권한 필요) | 이름 입력 + **학년**(고정 드롭다운: 초1~고3/N수) + **시즌명**(기존 시즌 자동완성, 새 이름 입력 시 자동 생성 — "2026 겨울방학 특강" 등) + **과목명**(기존 과목 자동완성, 새 이름 입력 시 자동 생성) + **담당 선생님**(기존 직원 이름 검색·선택 — `users` 모듈 Port 필요, 새 계정 발급 아님) + **교실명**(기존 교실 자동완성, 새 이름 입력 시 자동 생성) + 요일·시간대 복수 추가 UI (예: "월 3~5시" 행을 여러 개 추가). 저장 시 같은 교실·같은 요일/시간대가 이미 있으면 경고 후 등록 차단 |
| 강의 상세 | 강의 기본 정보(선생님/교실/요일·시간) + 수강생 목록(카드 또는 테이블) |
| 학생 상세 패널 | 강의 상세에서 학생 클릭 시 열리는 패널 — 이름/학년/학교/전화번호/부모님전화번호/특이사항 + 그 학생이 수강 중인 다른 강의 목록 |
