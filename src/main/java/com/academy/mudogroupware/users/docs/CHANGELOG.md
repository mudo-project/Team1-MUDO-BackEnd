# 📚 계정·권한(users) Changelog

## 2026-08-11 · 구성원 상세 조회 추가 🔍

- 관리자가 구성원 한 명의 상세 정보(이름/이메일/전화번호/역할/입사일/상태)를 조회할 수 있습니다.

## 2026-08-11 · 내 비밀번호 변경 추가 🔑

- 로그인한 사용자가 스스로 비밀번호를 바꿀 수 있습니다.

## 2026-08-11 · 내 정보 수정 + 계정생성 필드 선택화 ✏️

- 내 정보(연락처/이메일)를 직접 수정할 수 있습니다.
- 계정을 만들 때 연락처와 이메일을 비워둘 수 있습니다 — 나중에 본인이 채워 넣으면 됩니다.

## 2026-08-11 · 내 정보 조회 추가 👤

- 로그인한 사용자가 자기 정보(이름/이메일/전화번호/역할/입사일/상태)를 조회할 수 있습니다.

## 2026-08-11 · 학원 신청/승인 기능 제거 🗑️

- 학원을 새로 등록하는 신청/승인 절차(신청 접수, 목록/상세 조회, 승인, 반려)를 더 이상 지원하지 않습니다.
- 서비스가 학원 하나당 서버를 독립적으로 운영하는 방식으로 바뀌면서, 신규 학원을 앱 안에서 직접 등록할 필요가 없어졌습니다.
- 기존에 등록된 학원·구성원 데이터에는 영향이 없습니다.

## 2026-08-11 · 구성원 목록 조회에 페이지네이션·역할 필터 추가 📄

- 구성원이 많은 학원도 구성원 목록을 빠르게 조회할 수 있도록 페이지 단위로 나눠 받습니다.
- 특정 역할의 구성원만 골라 볼 수 있습니다(조직도 화면에서 역할별 탭으로 활용).

## 2026-08-11 · 구성원 목록에 오늘 근태 상태 추가 🕒

- 구성원 목록에서 각 구성원의 오늘 근태 상태(출근/미출근/휴무/휴가)를 바로 확인할 수 있습니다.
- 재직 중이 아닌 구성원은 근태 상태가 표시되지 않습니다.

## 2026-08-10 · 관리자용 구성원 목록 조회 추가 👥

- 관리자가 자기 학원 구성원 전체(퇴사자 포함)를 이름·이메일·연락처·역할·입사일·상태와 함께 한눈에 볼 수 있게 됐습니다.
- 이름이나 역할명으로 검색할 수 있습니다.

## 2026-08-10 · 학원 신청 접수 시점 아이디 중복확인 추가 🔍

- 학원 신청을 접수할 때 아이디(`requestedLoginId`)가 이미 쓰이고 있으면 그 자리에서 바로 알려드립니다 — 지금까지는 며칠 뒤 승인 단계에서야 알 수 있었습니다.
- 이미 발급된 계정뿐 아니라, 지금 검토 대기중이거나 이미 승인된 다른 신청서의 아이디와 겹쳐도 막습니다.
- 반려된 신청서의 아이디는 재사용해서 다시 신청할 수 있습니다.

## 2026-08-10 · 비밀번호 설정 링크 도입, 원장 계정 권한 정상화 🔑

- 계정 발급(원장 승인/직원 계정 생성) 시 임시 비밀번호가 응답에 평문으로 노출되던 방식을 없앴습니다 — 이제 비밀번호를 직접 설정할 수 있는 링크(`passwordSetupLink`)가 대신 내려갑니다.
- 새로운 계정은 이 링크로 이동해 아이디·임시 비밀번호(링크에 포함됨)·원하는 새 비밀번호를 입력하면 최초 비밀번호 설정이 끝납니다(`POST /api/users/password-setup`, 로그인 없이 호출 가능).
- 한 번 설정을 마치면 같은 링크는 다시 쓸 수 없습니다.
- 학원 신청이 승인되면 그 학원에 "원장" 역할이 자동으로 만들어지고, 그 시점에 존재하는 모든 권한이 함께 배정됩니다 — 지금까지는 원장 계정에 역할이 없어서 로그인해도 아무 기능도 못 쓰는 문제가 있었는데, 이번에 해결됐습니다.

## 2026-08-10 · 학원 신청 접수 추가 (계정 발급 체계 2단계 완결) 📝

- 계정 없는 학원이 로그인 없이 신청서를 낼 수 있게 됐습니다(공개 API).
- 학원명·대표자 이름/이메일/전화번호·로그인 아이디·플랜(무료/유료)을 받습니다.
- 사업자등록증 등 서류 제출·자동 검증은 이번엔 빠졌습니다 — SUPER ADMIN이 승인 단계에서 별도로 확인합니다.
- 신청 접수만으로 계정이 바로 생기진 않습니다 — 기존 목록/상세 조회·승인/반려 흐름 그대로 SUPER ADMIN이 검토 후 승인해야 학원과 원장 계정이 만들어집니다.

## 2026-08-09 · 직원 계정 발급 추가 (계정 발급 체계 3단계) 👤

- 학원 관리자(원장)가 로그인해서 자기 학원 소속 직원 계정을 직접 만들 수 있게 됐습니다.
- 계정을 만들 때 이름·연락처·이메일과 함께 배정할 역할을 지정합니다(역할은 필수입니다).
- 이미 쓰이고 있는 아이디로는 만들 수 없습니다.
- 계정 생성 시 임시 비밀번호가 함께 발급됩니다 — 지금은 관리자가 이 값을 직접 직원에게 전달해야 합니다(이메일 자동 발송은 다음 업데이트에서 추가될 예정입니다).

## 2026-08-08 · 역할 색상·인원수 표시 추가 🎨

- 역할을 만들거나 수정할 때 뱃지 색상(color)을 함께 지정할 수 있게 됐습니다. 색상 형식(hex 등)은 검증하지 않지만 최대 20자까지만 저장됩니다 — 넘으면 요청이 거부됩니다.
- 역할 목록·상세 조회 응답에 그 역할을 지금 쓰고 있는 재직 중인 구성원 수(memberCount)가 함께 나옵니다.

## 2026-08-08 · 학원 구성원 검색 API 추가 🔍

- 같은 학원 소속 구성원을 이름으로 검색하거나, 검색어 없이 전체 목록을 볼 수 있게 됐습니다.
- 워크스페이스나 채팅방을 만들 때 상대방의 userId를 찾는 용도입니다.
- 특정 권한 없이 로그인만 되면 누구나 쓸 수 있습니다 — 워크스페이스/채팅방 생성 자체가 아직 특정 권한으로 막혀있지 않기 때문입니다.

## 2026-08-08 · 사용자 역할 변경 추가 🔄

- 구성원의 역할을 같은 역할 또는 다른 유효한 역할로 바꿀 수 있게 됐습니다.
- 역할을 통째로 빼는(역할 없음으로 만드는) 건 이 기능으로 할 수 없습니다 — 유효한 역할로만 지정할 수 있습니다.

## 2026-08-07 · 역할 삭제 정책 조정 — 재직 중인 구성원 기준으로 변경 🔧

- 역할 삭제를 막는 기준이 "이 역할을 쓰는 사람이 한 명이라도 있으면"에서 "**재직 중인(ACTIVE)** 구성원이 쓰고 있으면"으로 바뀌었습니다.
- 퇴사자가 마지막으로 갖고 있던 역할도 이제 삭제할 수 있습니다 — 삭제하면 그 퇴사자의 역할 배정은 자동으로 해제됩니다.

## 2026-08-07 · 역할 삭제 추가 🗑️

- 더 이상 안 쓰는 역할을 삭제할 수 있게 됐습니다.
- 그 역할을 배정받은 구성원이 있으면 삭제가 거부됩니다 — 먼저 구성원들의 역할을 다른 역할로 바꾼 뒤에 삭제해야 합니다.
- 이걸로 역할 관리 기능(생성/목록/상세/수정/삭제/권한 조립)이 모두 갖춰졌습니다.

## 2026-08-07 · 역할 수정 추가 ✏️

- 역할의 이름과 설명을 바꿀 수 있게 됐습니다.
- 다른 역할과 이름이 겹치면 수정이 거부됩니다(단, 설명만 바꾸고 이름은 그대로 두는 건 문제없이 됩니다).
- 권한 목록은 이 기능으로 바꿀 수 없습니다 — 기존 권한 조립 기능을 그대로 씁니다.

## 2026-08-07 · 역할 상세 조회 추가 🔎

- 역할 하나를 골라 상세 정보(이름/설명/담긴 권한 목록)를 확인할 수 있게 됐습니다.
- 목록 조회에는 없던 권한 목록이 상세 조회에는 포함됩니다.
- 다른 학원의 역할을 조회하려고 하면, 역할이 아예 없는 것과 똑같이 "찾을 수 없다"고 안내됩니다 — 다른 학원 정보가 새어나가지 않도록 하기 위함입니다.

## 2026-08-07 · 역할 목록 조회 추가 📋

- 학원 안에 만들어둔 역할들을 목록으로 확인할 수 있게 됐습니다.
- 목록에는 이름/설명만 나오고 권한 목록은 안 나옵니다 — 역할 상세 조회(다음 업데이트)에서 확인할 수 있습니다.

## 2026-08-07 · 학원 신청 승인/반려 추가 ✅

- 슈퍼 어드민이 신청을 승인하면, 그 즉시 학원 계정과 최초 관리자(원장) 로그인 계정이 함께 만들어지고, 접속에 쓸 임시 비밀번호가 발급됩니다(최초 로그인 시 비밀번호 변경이 강제됩니다).
- 마음에 안 드는 신청은 사유를 남기고 반려할 수 있습니다.
- 이미 승인했거나 반려한 신청서를 다시 승인/반려하려고 하면 막힙니다.

## 2026-08-07 · 학원 신청 상세 조회 추가 🔍

- 슈퍼 어드민이 신청 목록에서 항목 하나를 골라 상세 정보를 볼 수 있게 됐습니다.
- 지금은 목록과 보이는 정보가 같지만, 나중에 화면 디자인이 정해지면 상세 화면에만 필요한 정보가 늘어날 수 있어 처음부터 별도 API로 분리해뒀습니다.

## 2026-08-07 · 학원 신청 목록 조회 추가 🏫

- 슈퍼 어드민이 들어온 학원 신청 목록을 확인할 수 있게 됐습니다.
- 신청서 작성(접수) 기능은 아직 없습니다 — 사업자등록증 파일 첨부 등 파일 업로드 기반이 먼저 갖춰진 뒤 별도로 추가될 예정입니다. 승인/반려 기능도 이어지는 업데이트에서 추가됩니다.

## 2026-08-07 · 슈퍼 어드민 계정 도입으로 모든 관리 기능 접근 가능 👑

- 슈퍼 어드민 계정으로 로그인하면 역할 할당 없이도 모든 관리 기능에 접근할 수 있게 됩니다.
- 플랫폼 관리자는 매 요청 역할 조회(roleId) 단계를 거치지 않고, JWT 클레임의 `accountType`/`adminScope` 값으로 즉시 식별되어 전체 권한이 부여됩니다.
- 학원 관리자(`admin_scope=ACADEMY`)는 컬럼으로 미리 준비되었으나, 아직 권한 로직이 미연동 상태입니다 — 향후 업데이트에서 활성화될 예정입니다.

## 2026-08-05 · 권한 카탈로그 조회 + 역할 권한 조립 API 추가 🔐

- 어떤 권한들이 있는지 목록으로 확인할 수 있게 됐습니다.
- 원장 등 권한 있는 계정이 역할에 원하는 권한을 골라 담을 수 있게 됐습니다 — 전체 교체 방식이라, 다시 담으면 이전 목록은 사라지고 새로 보낸 목록으로 바뀝니다(모두 빼고 싶으면 빈 목록을 보내면 됩니다).
- 존재하지 않는 권한을 담으려 하면 오류로 안내되고, 어떤 권한이 잘못됐는지도 함께 알려줍니다.
- 이제 역할 생성(전날 추가)에 이어 권한까지 담을 수 있어, 실제로 쓸 수 있는 역할을 만들 수 있게 됐습니다.

## 2026-08-05 · 역할 생성 API 추가 🏷️

- 원장 등 권한 있는 계정이 학원마다 원하는 역할(예: "강사", "조교")을 이름과 설명만으로 만들 수 있게 됐습니다.
- 같은 학원 안에서 이름이 겹치는 역할은 만들 수 없습니다.
- (참고) 역할 목록·상세 조회, 수정, 삭제, 권한 조립 API는 아직 포함되지 않았습니다 — 다음 업데이트에서 이어집니다.

## 2026-08-04 · 로그아웃 API 추가, 학원 소속 정보 무결성 강화 🚪

- 로그아웃할 수 있게 됐습니다. 로그아웃하면 서버에 저장된 로그인 유지 정보(refreshToken)가 즉시 삭제되고, 브라우저 쿠키도 함께 정리됩니다.
- 계정의 소속 학원 정보가 실제 존재하는 학원과 항상 일치하도록 데이터베이스 수준에서 보장하는 안전장치가 추가됐습니다(사용자 눈에 보이는 변화는 없습니다).

## 2026-08-04 · 학원별 맞춤 역할·권한 시스템의 기반 마련 🔑

- 학원마다 자유롭게 역할(예: "원장", "행정")을 만들고, 그 역할에 필요한 권한만 골라 담을 수 있는 구조의 기반이 만들어졌습니다.
- 로그인 토큰에 소속 학원 정보가 포함되어, 앞으로 다른 기능들이 "내 학원 데이터만" 더 안전하게 다룰 수 있게 됩니다.
- (참고) 역할을 실제로 만들고 권한을 담는 화면/API, 신규 직원 계정 발급 기능은 아직 포함되지 않았습니다 — 다음 업데이트에서 이어집니다.

## 2026-08-03 · 로그인 및 액세스 토큰 재발급 기능 최초 추가 ✨

- 아이디/비밀번호로 로그인할 수 있습니다. 로그인에 성공하면 액세스 토큰을 발급받습니다.
- 액세스 토큰이 만료돼도 다시 로그인하지 않고, 자동으로 새 토큰을 발급받을 수 있습니다. ♻️
- 같은 계정으로 다른 기기에서 로그인하면 이전 기기는 자동으로 로그아웃 처리됩니다(계정당 세션 1개).
- 아이디가 없거나 비밀번호가 틀려도 어느 쪽이 문제인지는 알려주지 않습니다 — 계정 정보 노출 방지를 위한 의도된 동작입니다. 🔒
- 퇴사·비활성 상태인 계정은 로그인할 수 없습니다.
- (참고) 회원가입/계정 발급, 로그아웃, 세부 권한(역할) 관리 기능은 이번에는 포함되지 않았습니다.
