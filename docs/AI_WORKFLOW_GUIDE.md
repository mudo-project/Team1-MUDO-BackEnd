# Superpowers 스킬 운영 가이드

AI 도구가 Superpowers 스킬을 사용할 때, 작업 위험도와 범위에 맞는 절차를 선택하기 위한 팀 공용 가이드입니다.

저장소의 `AGENTS.md`와 사용자 요청이 더 구체적인 경우에는 해당 규칙을 우선합니다.

## FAST — 직접 처리

다음 작업은 Superpowers 전체 절차를 사용하지 않습니다.

- 오타, 네이밍, 주석 수정
- DTO 필드 추가
- 단순 API 응답 변경
- 명확한 컴파일 오류
- 테스트 한두 개 수정
- 단일 파일 또는 2개 이하 파일 변경
- 개념 설명 또는 코드 분석

### 실행 방식

관련 파일만 확인 → 직접 수정 → 관련 테스트만 실행 → 변경 내용 요약

## STANDARD — 필요한 스킬 하나만 사용

일반적인 기능 개발이나 버그 수정에 적용합니다.

- Controller-Service-Repository 변경
- API 하나 추가
- 검증 로직 추가
- 조회 쿼리 변경
- 예외 처리 추가
- 약 3~5개 파일 변경

### 실행 방식

요구사항이 명확한 기능은 짧은 구현 계획 → 직접 구현 → 관련 테스트 → 한 번의 코드 검토 순서로 진행합니다.

원인이 불명확한 버그는 `systematic-debugging`으로 원인을 확인한 뒤 수정하고 회귀 테스트를 실행합니다.

## FULL — Superpowers 전체 사용

위험도가 높거나 설계 검증이 필요한 작업에만 전체 워크플로를 적용합니다.

- 인증·인가 또는 Spring Security 변경
- 예약·결제·동시성 제어
- 트랜잭션 경계 변경
- DB 스키마 및 Flyway 마이그레이션
- 멀티모듈 또는 아키텍처 변경
- Spring–FastAPI 등 외부 시스템 연동
- 대규모 리팩터링
- 요구사항이 모호한 신규 기능

## 공통 원칙

- 작업 위험도와 범위에 맞는 최소 절차를 선택합니다.
- 모든 작업에 다단계 계획·에이전트 분업·반복 리뷰를 적용하지 않습니다.
- 핵심 비즈니스 로직과 고위험 변경은 관련 테스트로 검증합니다.
- AI 도구를 사용하더라도 도메인 소유권, API 계약, DB 마이그레이션, 보안 규칙은 저장소 문서를 우선합니다.

## 확장 가이드

새 AI 도구나 스킬 사용 규칙이 필요해지면, 해당 도구·스킬의 목적과 적용 조건, 금지·주의 사항을 이 문서에 추가합니다.
